# /os/ · рабочая инструкция для будущего Клода

Портал одного дня. Адрес: `https://sychinnikov.com/os/` (за Cloudflare Access, путь `/os/*` гейтом покрыт, проверено 04.08.2026).
Зеркало `https://sychinnikov-portal.pages.dev/os/` анонимно отдает статику, поэтому данные закрыты функцией `functions/os/data/_middleware.js`.

Спецификация целиком не в этом репозитории: она собрана в сессии 04.08.2026 и коротко пересказана здесь. Если правишь портал, сначала прочитай этот файл до конца.

## 1. Кто пишет какой файл

| Файл | Кто пишет | Кто не пишет никогда |
|---|---|---|
| `os/data/os.json` | только `Claude-Context/.scripts/portal-build/build_os.py` | человек, любой другой скрипт, любой шаг ритуала |
| `os/data/days/ГГГГ-ММ-ДД.json` | только `build_os.py` (замораживает снимок при закрытии дня) | все остальные |
| `os/data/history.json` (Фаза 2) | только `build_os.py` | все остальные |
| `os/index.html`, `os/ritm.html` | Клод руками, в разметке нет ни одной цифры и ни одного имени | генератор |
| `os/assets/os.css`, `os/assets/os.js`, `os/assets/favicon.svg` | Клод руками | генератор |
| `os/README.md` | Клод руками | генератор |
| `functions/os/api/*.js`, `functions/os/data/_middleware.js` | Клод руками | генератор |
| ключи KV `os:*` | функции `input.js`, `pull.js`, `ping.js` | генератор, статика |

Проверка подписи Access живет в одном месте, `functions/os/api/_shared.js`, и сверяет издателя, **получателя** (`aud` приложения `sychinnikov.com`), срок годности и подпись. Сверка `aud` обязательна: Cloudflare подписывает одним набором ключей команды токены всех приложений домена, и без нее сюда прошел бы токен любого соседнего приложения. Тот же пробел остался в `functions/fishok/api/board.js`, откуда код изначально переносился: если будешь править доску Fishok, перенеси проверку туда.

**Правило единственного писателя.** Все, что лежит в `os/data/`, пишет ровно один скрипт: `build_os.py`. Если понадобилось положить туда цифру другим путем, значит выбран неверный путь: цифра должна появиться в файле системы, а генератор ее заберет.

**Правило пустого HTML.** В разметке нет чисел, сумм, имен людей и дат. Есть только контейнеры с `data-slot`, которые заполняет `os.js` из `os.json`. Если в HTML появилась цифра, она протухнет и начнет врать: именно так умерла старая главная.

**Правило честного возраста.** Каждое значение приходит формой `{value, source, as_of, age_days}` либо `{error, source}`. Непрочитанное значение показывается как красное «не прочитана» с причиной. Старое значение вместо нового не показывается никогда.

## 2. Чего в `/os/` не делать

1. Не заводить страницы контуров (`/os/fishok/`, `/os/ff/`, `/os/dengi/`), хабы и переходники. Контур присутствует меткой на ходе дня и числом в полосе досок.
2. Не заводить восьмую доску с карточками и Гант. Досок в портале уже семь, запись работает у одной.
3. Не добавлять седьмой блок на главный экран. Новый блок появляется только вместо старого. Потолок жесткий: одно главное действие плюс до трех ходов, до пяти строк денег в воздухе.
4. Не добавлять третью страницу. Их две: `index.html` и `ritm.html`.
5. Не подключать CDN, внешние шрифты, npm, сборщик и фреймворк. Один HTML, один CSS, один JS, системные шрифты, ноль внешних запросов.
6. Не делать кнопку «запустить day-close». Клод живет в терминале на Маке. Портал кладет заявку в KV и показывает строку команды для копирования, честно называя это заявкой.
7. Не делать ручной ввод денежных фактов (оплата, трата). Цифра денег рождается из первички, а не в браузере (ADR-009).
8. Не читать `founder-finance/data.json`: он правится руками и расходится сам с собой. Единственный источник по Founder Finance это `founder-finance/pipeline.json`.
9. Не читать `this-week.md`: файл содержит два плана сразу и сам про себя пишет, что устарел.
10. Не трогать ключ KV `latest` и клиентскую доску Fishok. Наши ключи только с префиксом `os:`.
11. Не трогать публичный слой (`/foundertrajectory*`, `/founderfinance`, `/landing`) и клиентские поверхности (`/fishok/*`). Только ссылаться.
12. Не строить `/os2/`. Если портал не работает, чинится механика ввода, а не дизайн (см. раздел 4).

## 2а. Открытый репозиторий: почему данных пока нет на сервере

Репозиторий портала на GitHub **публичный** (проверено 04.08.2026: `visibility: public`). В `os/data/` лежат остатки счетов, суммы офферов, имена людей и запись наставника целиком. Замок `functions/os/data/_middleware.js` закрывает путь по сети, но git публикует те же байты в обход него, и навсегда: история коммитов не забывает.

Поэтому `deploy.sh` спрашивает у GitHub видимость репозитория и, пока она не `private`, **исключает `os/data/` из коммита**. Портал при этом собирается и выкладывается, а `os.json` на сервере отсутствует, и экран честно пишет «снимок дня не загрузился».

**Что делать:** в настройках GitHub сделать репозиторий приватным. Cloudflare Pages штатно собирает приватные репозитории, деплой не сломается. После этого данные поедут сами, править ничего не нужно: замок в `deploy.sh` снимется по факту.

Второй возможный путь, если репозиторий обязан остаться публичным: держать `os/data/` вне git и отдавать снимок дня функцией из KV. Это отдельная работа, в Фазе 1 ее нет.

## 3. Как устроен обмен событиями

```
браузер Андрея                 Cloudflare KV                  Клод в терминале
   |                                |                                |
   | PUT /os/api/input              |                                |
   |  {events:[...]}   ------------>| os:ev:<дата>:<мс>-<4 симв.>    |
   |                                | os:request (если kind=request) |
   |                                |                                |
   | GET /os/api/state?d=ГГГГ-ММ-ДД |                                |
   |<------ события дня ------------|                                |
   |  (экран переживает перезагрузку и смену устройства)             |
   |                                |                                |
   |                                |<---- GET /os/api/pull ---------|
   |                                |----- события после курсора --->|
   |                                |                                | применяет в файлы
   |                                |                                | пишет копию в
   |                                |                                | Claude-Context/os-events/
   |                                |<---- POST {ack_until} ---------|
   |                                | os:cursor двигается,           |
   |                                | подтвержденные ключи удалены   |
```

Правила обмена:

- **Одно событие, один ключ KV.** Никакого чтения-правки-записи целого документа: два быстрых клика и два устройства не затирают друг друга.
- **Отправка на клик**, а не на уход со страницы. Доска Fishok мирроила снимок по `visibilitychange` и поэтому молчала 26 дней. Не повторять.
- **Очередь на клиенте** в `localStorage` (`os.queue.v1`) с повтором: экран меняется сразу, сеть догоняет.
- **Авторизация.** `PUT /os/api/input` только по подписи Access JWT (заголовок `Cf-Access-Jwt-Assertion`). `GET /os/api/pull` и `POST /os/api/pull` только по `Bearer BOARD_READ_TOKEN` (Клод ходит через pages.dev, вне гейта). `GET /os/api/state` и `/os/data/*` принимают и то, и другое.
- **Биндинг и токен уже есть.** `FISHOK_BOARD` и `BOARD_READ_TOKEN` видны функциям под `/os/` (проверено живым ответом `/os/api/ping` 04.08.2026). Новых биндингов заводить не нужно, в панель Cloudflare ходить не нужно.
- **Только метод PUT и только своя страница.** `POST /os/api/input` не существует намеренно: простой POST уходит с чужой страницы без предварительного запроса CORS. Дополнительно сверяются заголовки `Sec-Fetch-Site` и `Origin`, чужой источник получает 403.
- **Дата события зажата сервером.** Ключ строится из даты, а по ключу работает курсор. Дата с клиента принимается, только если она настоящая и отстоит от сегодняшней не больше чем на сутки; иначе берется серверная, а присланная кладется в поле `client_date`. Без этого одно устройство со сбитыми часами навсегда увело бы курсор в будущее, и разбор молча отдавал бы пустоту.
- **Очередь чистится поименно.** Ответ `input.js` несет `accepted` (легло в KV) и `skipped` (отбито разбором, повтор не поможет). Если запись в KV не прошла, событие уходит в `retry`, ответ 503, и `os.js` оставляет его в очереди. Отвечать 200 на неудачную запись нельзя: это тихая потеря нажатия.
- **Подтверждение только настоящим ключом.** `ack_until` обязан целиком совпадать по виду `os:ev:ГГГГ-ММ-ДД:<мс>-<хвост>`, иметь дату не позже сегодняшней и физически лежать в KV. Иначе 400. Причина: подтверждение удаляет все ключи не выше названного, и обрезок вроде `os:ev:9` стер бы очередь целиком.
- **Аварийный выход.** `python3 os_pull.py --reset-cursor` стирает `os:cursor`, события не трогает. Единственное лекарство, если курсор все же уехал вперед.
- **Идемпотентность.** События применяются по `ref`, последнее по `ts` побеждает. Повторный разбор одного ключа невозможен: после `ack` ключ удален, курсор сдвинут. Повторы одного и того же события (потерянный ответ, две вкладки) отсеиваются в `os_pull.py` по `client_id`.
- **Срок жизни события 120 дней.** KV не архив. Архив это `Claude-Context/os-events/ГГГГ-ММ-ДД.json`, его пишет Клод после разбора.

Виды событий (`kind`) и что Клод делает с каждым, описаны в скилле `/day-close`, шаг 00. Список закрытый: `main.done`, `move.done`, `move.postpone`, `air.answered`, `day.close`, `note`, `question.answer`, `request`, `debt.dismiss`. Новый вид добавляется одновременно в трех местах: белый список в `input.js`, обработчик в `os.js`, таблица применения в скилле `/day-close`.

**Контракт с Клодом (нарушение убивает портал за неделю).** То, что Андрей ввел на портале, в чате не переспрашивается ни в каком виде: маркеры энергия, P1, деньги, текст «что двинулось», «семя на завтра», отметки сделанного и результаты ходов. Портал обязан физически сокращать вечернюю сессию, а не дублировать ее.

## 4. Критерий смерти, проверка 18.08.2026

Портал считается неработающим, если к 18.08.2026 верно хотя бы одно:

- в KV меньше 20 событий за 14 дней после запуска;
- либо `/os/` не открывался пять дней подряд.

Проверка выполняется одной командой:

```bash
python3 ~/Диск/AI/Claude-Context/.scripts/portal-build/os_pull.py --stats
```

Результат записывается отдельной записью в `Claude-Context/decisions.md` в тот же день. Если критерий сработал, чинится механика ввода (что именно не нажалось и почему), а не дизайн. Строить второй портал вместо этого запрещено.
